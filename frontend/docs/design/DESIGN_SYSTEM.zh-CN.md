# PaperTrace 设计规范

> 适用范围：PaperTrace 前端的所有页面（开始页、加载页、报告页、报告列表、失败页）。
> 本文只写**现行规范**：要遵守的约束、数值和用法，不记录设计过程。改规范时直接改本文，并同步改 `src/styles/theme.css`。
> 结构参考了 Microsoft Fluent 2、Apple Human Interface Guidelines 和 GOV.UK Design System：先讲基础（颜色、字体、间距等），再讲组件，再讲模式和页面。每个组件都写"什么时候用 / 什么时候不用 / 怎么用"。

## 1. 产品与原则

**产品要回答的问题：这篇论文有没有可疑之处？**主张有没有论文内证据支持、引用是否真实、有没有可用代码。"值不值得读"（五维评分）是附带信息，视觉地位永远低于可信度核查。

### 四条原则

| 原则 | 含义 | 在界面上的体现 |
|---|---|---|
| **证据优先** | 每个结论都能回到原文 | 判断旁边一定有原文摘录和页码；点击就能在 PDF 上看到高亮 |
| **不确定要说出来** | "没查完"和"查出问题"是两回事 | 兜底分、未核实用石板灰加斜纹；只有查出的问题用红色 |
| **安静的专业感** | 像 Office 或 Acrobat 这样的工具，不像营销页 | 偏蓝的白底、细线分隔、6px 以内的圆角；不用渐变大字、发光、表情符号 |
| **动效只为说明变化** | 动画告诉用户"东西从哪来、到哪去" | 只有放大缩小、淡入淡出、数值滑动三类动效；不弹跳、不模糊、不视差 |
| **每样信息只出现一次** | 同一个数字、同一句说明、同一个入口不在两处重复 | 计数只放在组件导航栏；评分规则版本只写在状态栏；只为演示用的控件（如动画重放）不进产品 |

## 2. 基础

### 2.1 颜色

所有颜色都通过 token 使用，**禁止在组件里写死色值**。token 名对应 `theme.css` 里的 `--color-*`。

**界面中性色**

| Token | 值 | 用途 |
|---|---|---|
| `canvas` | `#F4F7FB` | 页面底色（偏蓝的白） |
| `surface` | `#FFFFFF` | 卡片、面板、输入框 |
| `surface-alt` | `#F6F8FB` | 右侧组件区底色 |
| `chrome` | `#E8EEF5` | 标题栏 |
| `rail` | `#EFF3F8` | 两侧图标栏、状态栏 |
| `paper-bed` | `#E5EAF0` | PDF 页面下面的底 |
| `ink` | `#1F2328` | 正文、数字 |
| `muted` | `#5F6B76` | 次要文字、说明 |
| `line` | `#DFE6EE` | 边框、分隔线 |
| `line-strong` | `#C9D4E0` | 悬停时的边框、虚线框 |
| `hairline` | `#EDF1F5` | 列表行之间的细线 |

**品牌蓝（Outlook 蓝阶）**：代表"可信、已核实、可操作"。

| Token | 值 | 用途 |
|---|---|---|
| `blue-100` | `#E3EFFA` | 选中底色、标签底色 |
| `blue-200` | `#B9DDFA` | 体积材质的高光端 |
| `blue-400` | `#3A9CE8` | 体积材质、渐变 |
| `blue-500`（`accent`） | `#0078D4` | 主按钮、链接、选中线、图标强调 |
| `blue-600`（`accent-strong`） | `#005A9E` | 悬停、标签文字 |
| `blue-700` | `#0062B1` | 体积材质暗部 |
| `blue-800` | `#004A88` | 体积材质最暗端 |

**石板灰（缺口与兜底）**：代表"没查完、查不到、兜底分"，**不代表有问题**。

| Token | 值 | 用途 |
|---|---|---|
| `slate-100` | `#EDF1F3` | 兜底材质亮端 |
| `slate-300` | `#B4C0C6` | 兜底材质 |
| `slate-400` | `#95A3AA` | 兜底标记 |
| `slate-500` | `#7A8890` | 兜底徽标 |
| `slate-600`（`gap`） | `#66737A` | 兜底文字、未核实标签 |

**语义色**

| Token | 值 | 规则 |
|---|---|---|
| `concern` | `#D13438` | **只用于"查出的问题"**（`finding.kind = concern`）和"Contradicted"判定 |
| `concern-soft` | `#FBE9EA` | 问题标签底色 |

**禁止**：绿色表示"通过"，黄色或橙色表示"警告"。这两种颜色在本产品里会显得廉价、像 AI 生成。"通过"用蓝，"不确定"用石板灰，"有问题"用红。

**分数色阶**：总分仪表从低到高用 `#A7B3BF → #86A6C8 → #2A86D6 → #0067B8`，灰代表可疑，蓝代表可信。中间色用 `color-mix(in oklch, …)` 计算，渐变一律用 `in oklch` 插值，避免发灰发脏。

**证据高亮色**（叠在 PDF 上，`mix-blend-mode: multiply`）

| 类型 | 底色 | 下划线 |
|---|---|---|
| 支持判断的段落 | `rgba(0,120,212,.17)` | 2px 实线 `rgba(0,120,212,.9)` |
| 主张原文位置 | `rgba(105,121,126,.14)` | 1.5px 虚线 `rgba(105,121,126,.9)` |
| 已核实的引用 | `rgba(0,120,212,.08)` | 无 |
| 未核实的引用 | 同主张原文 | 同主张原文 |
| 悬停 | `rgba(0,120,212,.26)` | 不变 |
| 选中 | `rgba(0,120,212,.30)` | 2px 实线，外加 2px 蓝色外框 |
| 已看过 | `rgba(0,120,212,.05)` | 1px 实线 |

| 角色 | 字体 | 字重 | 用在哪里 |
|---|---|---|---|
| 标题、数字 | Shippori Mincho（衬线） | 600 / 700 | 页面标题、组件里的小标题、所有分数、引文 |

| 代码、ID | `ui-monospace, Menlo` | 400 | 报告 ID、arXiv 号、代码片段 |

| `title-s` | 16 | 22 | 衬线 700 | 组件内标题 |
| `title` | 19 | 26 | 衬线 700 | 等级文字（"Some concerns"） |

### 2.3 间距

4px 网格，与 Fluent 2 一致：`2 · 4 · 6 · 8 · 10 · 12 · 16 · 20 · 24 · 32`。

- 组件内边距：12–14px。
- 组件之间：10px。
- 页面左右留白：桌面 24px，手机 16px。
- 列表行：上下 7–9px，行之间用 `hairline` 分隔线，不用卡片套卡片。

### 2.4 圆角

| Token | 值 | 用途 |
|---|---|---|
| `radius-xs` | 2px | 证据高亮、缩略图 |
| `radius-sm` | 4px | 标签、小按钮、输入框、列表行悬停底色 |
| `radius-md` | 6px | 卡片、面板、主按钮、菜单、玻璃浮层 |
| `radius-full` | 999px | 只用于计数徽标、圆点、旋钮、指示珠 |

**6px 是上限。**大圆角会显得像 AI 生成，不要用 8px 以上的圆角做卡片。

### 2.5 层级（阴影）

阴影色统一用 `rgb(10 44 86)`，是带蓝的深色，不用纯黑。

| Token | 用途 | 值 |
|---|---|---|
| `shadow-0` | 嵌在页面里的面板 | 无，只用 1px `line` 边框 |
| `shadow-1` | 组件卡片 | `0 1px 2px /5%`、`0 8px 18px -16px /40%` |
| `shadow-2` | 玻璃工具栏、悬浮卡片、菜单 | `0 12px 28px -18px /45%`、`0 2px 6px -3px /18%` |
| `shadow-3` | 下拉菜单、对话框 | `0 24px 48px -24px /50%`、`0 4px 12px -6px /20%` |

### 2.6 材质

**玻璃**：只用于浮在内容上面的东西，包括命令栏、悬浮证据卡、菜单。

- 白色 66% 透明 + `backdrop-filter: blur(16px) saturate(180%)`。
- 顶部 1px 内高光 + 底部内阴影 + `shadow-2`。
- 左上角加一层很淡的径向高光。
- 圆角不超过 6px。**不使用折射效果**（SVG 位移滤镜只在 Chromium 生效，而且容易显得花哨）。
- **不要用于**：正文卡片、按钮、整页背景。

**体积**：只用于分数和进度相关的组件，包括小分的旋钮、温度管、光珠条，总分指示珠，进度轨道。

- 凹槽（`groove`）：上暗下亮的竖向渐变 + 顶部内阴影 + 底部 1px 白色高光，表示"嵌进去的轨道"。
- 光照材质（`lit`）：`blue-200 → 400 → 500 → 700 → 800` 竖向渐变 + 底部内暗边，表示"有厚度的填充物"。
- 兜底材质：把蓝换成石板灰阶，再叠 135° 斜纹（2px 线、6px 间隔）。
- 光源统一在**左上方**：高光偏左上，阴影偏右下。
- **不要用于**：按钮、卡片、文字。

### 2.7 图标

- 图标集：**Fluent UI System Icons**（MIT），统一使用 `20_regular` 线性版本。不混用其他图标集，不用表情符号。
- 尺寸：命令栏和导航栏 18–20px，按钮内 14–16px，正文行内 14px。
- 颜色：默认 `muted`；选中或强调用 `accent`；不给图标单独加彩色。
- 只用图标的按钮必须有 `title` 和 `aria-label`。
- 固定的语义：

| 含义 | 图标 |
|---|---|
| 主张与证据 | `text_quote` |
| 参考文献 | `book_open` |
| 代码与复现 | `code` |
| 总分 / 判定 | `gauge` |
| 证据导航 | `highlight` |
| 核查过程 | `timeline` |
| 上手引导 | `lightbulb` |
| 支持 | `checkmark_circle` |
| 部分支持 | `circle_half_fill` |
| 矛盾 | `warning` |
| 无法判断 | `question_circle` |

### 2.8 动效

采用 Fluent 2 的时长与曲线 token，不自定义其他值。

| 时长 Token | 值 | | 曲线 Token | 值 |
|---|---|---|---|---|
| `duration-faster` | 100ms | | `ease-decelerate-max` | `cubic-bezier(0.1,0.9,0.2,1)` |
| `duration-fast` | 150ms | | `ease-decelerate-mid` | `cubic-bezier(0,0,0,1)` |
| `duration-normal` | 200ms | | `ease-accelerate-mid` | `cubic-bezier(1,0,1,1)` |
| `duration-gentle` | 250ms | | `ease-easy` | `cubic-bezier(0.33,0,0.67,1)` |
| `duration-slow` | 300ms | | `ease-easy-max` | `cubic-bezier(0.8,0,0.2,1)` |
| `duration-slower` | 400ms | | | |

**用法**

| 场景 | 时长 | 曲线 |
|---|---|---|
| 悬停、按下的颜色变化 | 100ms | `ease-easy` |
| 菜单、悬浮卡出现 | 150ms | `ease-decelerate-mid` |
| 菜单、悬浮卡消失 | 100ms | `ease-accelerate-mid` |
| 组件折叠和展开 | 200ms | `ease-easy` |
| 页面间放大缩小（容器变换） | 300ms | `ease-easy-max` |
| 顶层导航切换 | 150ms 淡入淡出 | `ease-easy` |
| 进度条推进 | 400ms | `ease-decelerate-mid` |
| 分数从 0 滑到最终值（每次重新进入视野、展开所在组件或切回标签页时都重播） | 1500ms（小分 1300ms） | 三次缓出 |
| 列表依次出现 | 每项错开 60ms，最多 5 项 | `ease-decelerate-mid` |

**禁止**：回弹（spring overshoot）、模糊过渡、视差、整页滑动、循环的装饰性动画。加载中唯一允许的循环动画是进度表盘和细分条上的流光（表盘一圈 5s，细分条 4.6s）。

**减少动效**：系统开启"减少动态效果"时，所有过渡改为 100ms 以内的淡入淡出，分数直接显示终值，流光停止。

## 3. 组件

组件都在 `src/ui/`。页面只组合组件，不在页面里重新画按钮、标签这类基础元素。

### 3.1 总分仪表 `ScoreGauge`

**用途**：报告页显示总的可信度试验分（0–10）。五维评分页 `/score/$id` 的总分用它的小号（168px，不显示两端数字和副标题，分带用五维的 5.5 / 7 / 8.5），这样五维分在视觉上始终低于可信度分。
**不要用于**：核查进度（用 3.1b 的进度表盘）；单项分数（用 3.2 的小分）；可信度报告里的五维摘要。

**尺寸**：宽度由 `--gauge-size` 给定（默认 212px），格子更窄时整体缩小。弧粗、指示点、端点、分带缝和数字都按仪表实际宽度的比例换算（CSS 容器单位 cqi，以 212px 为基准：弧 11px、指示点 23px、数字 56px），所以任何尺寸下比例都一样，数字不会压到弧上。

**结构**

- 270° 开口细弧：从左下（225°）顺时针到右下（135°），粗 11px，两端圆头。
- 弧的颜色用分数色阶，由灰到蓝。
- 弧上 3 道 3px 的缝，位置在 3、6、8 分，对应四个等级的分界。
- 指示珠：直径 23px 的白色体积珠，中心 9px 圆点取当前分数对应的颜色；外圈 3.5px 抠白，与弧分开。
- 中心是分数（`score-l`）和"/ 10"（`caption`，muted）。
- 弧的两个端点下方标 0 和 10。
- 弧下方是等级文字（`title`）和一行说明（"Trial score · rubric 0.2, provisional"）。

**状态**

| 状态 | 表现 |
|---|---|
| 出分 | 指示珠从 0 滑到分数，用时 1500ms；等级文字在滑动结束后淡入 |
| 无分 | 中心显示 "—"，等级写 "Not assessed"，说明写原因 |

**尺寸**：默认直径 212px，最小 160px。

### 3.1b 进度表盘 `ProgressDial`

**用途**：加载页显示整次核查的进度（0–100%），参考测速网的表盘。
**不要用于**：分数。

**结构**（全部画在同一个 SVG 坐标系里，整体等比缩放，任何尺寸下都不会互相挤压）

- 240° 开口弧，粗 12，两端圆头；底色 `#E1E8F0`。
- 进度填充沿弧线增长，颜色由 `blue-200` 渐变到 `blue-700`，带一层淡蓝投影。
- 流光：一道长而柔和的白光沿弧流过已经走过的部分，一直流到末端的圆头里，像水流划过；不能是一小段亮块，也不能看出分层或颗粒。实现：表盘上叠一个 CSS 层，最里面是一条锥形渐变光带（约 70°，两头对称渐变，峰值亮度约 38%），整层匀速旋转，一圈 5 秒。外层遮罩就是已填充弧的准确形状：圆环 ∩ 已填充扇形，再加两端的圆头。中间一层从左到右的静态遮罩把光从 100% 压到 55%，因为白光在浅色起点几乎看不见、在深色末端很显眼。光带转过底部缺口和未填充部分时看不见，自然形成间歇。动画只改 `transform`，由 GPU 合成，不逐帧重绘 SVG。细分进度条用同样的长渐变光带（峰值 30%），也只移动 `transform`。
- 弧内 21 根刻度，每 25% 一根主刻度；已经走过的刻度变蓝。弧外只标 0、25、50、75、100。
- 指针：细长锥形，从蓝渐变到墨色；中心是白色圆钮加蓝点。
- 百分比放在弧底开口处（衬线 32，单位 % 用正文字体 16），不与指针、刻度重叠。
- 表盘下方三行，各自固定高度，文字变化时下方元素不跳动：
  1. 阶段名（15px，700，`accent-strong`），如 "1 of 3 checks complete"。
  2. 字幕：一行文字，每 3.2 秒轮流显示各项检查此刻在做什么（"Claims — evaluating claims against the evidence"），新的一行从下方滑入。
  3. 剩余时间范围加已用时间："Estimated 5–10 min remaining · 3 min elapsed"。剩余时间按最慢的那项检查估算，给区间而不是精确秒数。

**行为**：数值只增不减（估计值被真实事件替换时也不回退），每次变化用 500ms 缓出滑动。

### 3.2 小分 `ScoreKnob` · `ScoreTube` · `ScoreBead`

每个检查固定配一种形态，**不混用**：

| 检查 | 组件 | 形态 |
|---|---|---|
| 主张与证据 | `ScoreKnob` | 62px 白色体积旋钮，外圈 21 根刻度，点亮到当前分数 |
| 参考文献 | `ScoreTube` | 14px 高的玻璃温度管，凹槽里是光照材质的"液体"，下方标 0 / 5 / 10 |
| 代码与复现 | `ScoreBead` | 8px 凹槽量程条，填充渐变 + 18px 白色光珠 |

- 数字（`26px` 衬线）永远在图形左边或旁边，图形只是辅助。
- 兜底分：材质换成石板灰加斜纹，旁边的标签写 "Fallback score"。
- 进入视口时从 0 滑到分数，用时 1300ms。

### 3.3 判定与状态标签 `OutcomePill` · `VerdictLabel`

- 圆角 4px，11px 字号，700 字重，内边距 1×7px，不换行。
- 主张判定：
  - Supported：蓝底蓝字。
  - Partly supported：浅蓝灰底，加 1px 描边。
  - Contradicted：`concern-soft` 底，`concern` 字。
  - No support found / Undetermined / Not checked：石板灰。
- 引用：Matched 用蓝，Could not verify 用石板灰。
- 等级文字（Critical / Significant / Some / No significant concerns）**不做成彩色标签**，用衬线标题字直接写出来。

### 3.4 按钮 `Button` · `IconButton` · `Chip` · `PageChip`

| 类型 | 外观 | 用途 |

### 3.8 证据高亮 `Highlight` 与悬浮卡 `EvidenceCard`

- 高亮按 2.1 节的颜色规则，画在 PDF 的叠加层上；同一行相邻的片段合并成一块。
- 主张证据在页面右侧外边距有一根 6px 的蓝色竖条，方便快速扫读。
- **悬浮卡**：
  - 玻璃材质，宽 330px。
  - 顶行：图标 + 编号 + 类型 + 判定标签。
  - 中间：主张原文，衬线 14px。
  - 下面：页码和章节。
  - 底部操作行：Copy quote、Show in Claims、Mark reviewed。
- 悬停 240ms 后出现；鼠标移进卡片时不消失。触屏上改为点击打开。
- 点击高亮会选中它：右侧对应的主张行高亮，证据组件切换到这一条。

### 3.9 进度日志 `ActivityLog`

加载页的核心组件，见 4.1。它是一个**滚动日志**：固定显示最近 4 条大事件的高度，新事件从底部进入，旧事件向上滚出，顶部 22px 渐隐。页面因此不会随事件变多而变长。

- 每行：状态图标加一句话，不显示每一步的计时。
- 只记**大事件**，按实际发生时间排序：排队、取得论文、解析完成、三项检查开始、每项检查完成（部分完成写 "with gaps"）、阅读摘要就绪、生成报告、报告就绪。还没发生的步骤不显示。
- 检查内部的小步不进日志，只用在表盘下方的字幕里。
- 三项检查各自的进度放在日志上方的**细分**里：图标、名称、4px 细进度条、小字百分比（完成后写 Done / With gaps）。百分比只是细分，主数字永远是表盘上的总进度。
- 状态图标：
  - 完成：蓝色实心对勾。
  - 进行中：带流光的蓝色细环。
  - 等待：空心灰圈。
  - 部分完成：石板灰半圆。
  - 失败：红色感叹号。
- 新的一行用 150ms 从下方 4px 淡入；不自动滚走用户正在看的内容。
- "进行中"那一行可以带一条进度轨道（凹槽 + 光照材质）。
- 文案：现在时，句子式，不带技术细节。写 "Checking 49 references"，不写 "reference_source_agent call #3"。

### 3.10 模型选择 `ModelPicker`

- 何时用：开始页输入卡里选择核查用的模型。后端 `/v1/models` 列出的模型多于一个时才出现。
- 列表只来自后端（合同 7.2：前端不维护第二份清单）。前端只按 `provider` 字段配厂商标志（`ProviderMark`：Claude、OpenAI、DeepSeek；未知厂商显示首字母圆片），不显示 `model_version` 这类具体型号。
- 触发按钮：高 32px，白底细描边，左边厂商标志，中间 `display_name`，右边箭头。打开时描边变蓝并加 3px 浅蓝光圈，箭头转 180°。
- 列表：玻璃材质（95% 白，保证下层按钮不透出来），宽 330px，从按钮右下方展开。展开动画 250ms `ease-decelerate-max`：从上方 6px、97% 大小淡入；各行再错开 30ms 上浮。
- 每行：22px 厂商标志 + 名称（粗体）+ 后端给的说明（可换行）。当前选中项右侧一个蓝色勾。
- 后端列出但不能用于核查的模型（`is_available=false`，或厂商不在可信度核查支持范围内）照样显示，置灰、标志去色，右侧标 "Unavailable"，不能选。这样模型目录在启用前后看起来一致。
- 键盘：按钮上 ↑/↓ 打开；列表里 ↑/↓ 在可选项之间移动（跳过不可用项）、Home/End、Enter/空格选择、Esc 关闭并把焦点还给按钮、Tab 关闭。点列表外关闭。用 `listbox` / `option` 语义和 `aria-activedescendant`。

### 3.11 帮助助手 `Assistant`

- 右下角 48px 圆形按钮（蓝色光照材质 + chat_sparkle 图标），报告页上移到组件栏左侧、状态栏上方。点开是 400 × 600 的玻璃对话窗，从右下角缩放展开；手机上铺满底部。
- 结构参照 Ant Design X（Welcome / Prompts / Bubble / Actions / Sender）和 Copilot 的做法，但只用本系统的蓝色与 Fluent 图标，不用彩虹渐变：
  - 欢迎区：大号蓝色球形标志、"How can I help with PaperTrace?"、一句话说清能做什么、不做什么（不评价论文本身）。
  - 起步问题按页面分组："On this page"（首页、等待页、报告、五维、历史各两条）+ "General"（两条）。卡片带图标，悬停变浅蓝。
  - 回答：左侧小号标志 + 无底色正文；首个字到达前显示 "Thinking" 和三个依次跳起的点，之后逐字流式显示带闪烁光标；可停止。
  - 回答下方：复制、有用、没用。评价发到助手服务的反馈记录（`assistant/feedback.jsonl`），供维护知识库时查看。
  - 输入区：输入框和发送按钮在同一个圆角框里，聚焦时整框亮蓝边；上方一枚小胶囊写明"这页分享了什么"（悬停看全文），下方一行免责说明 "AI-generated answers may be inaccurate; check them against the report."
  - "New conversation"（compose 图标）清空。对话存在本标签页（sessionStorage）。
- 只回答使用 PaperTrace 和理解报告的问题，知识来自 `assistant/guide.md`；在报告页会附上当前报告的摘要（分数、类别、问题与缺口数、兜底项），不发送全文。用户用什么语言提问就用什么语言回答。
- 后端是独立的小服务 `assistant/server.mjs`（Node，无依赖，默认 8020 端口，`/assistant/chat` 返回 SSE，`/assistant/feedback` 记录评价），不在评分后端里；密钥只在服务端。每个地址 5 分钟内最多 20 次。
- 知识库维护见 `assistant/README.md`：`guide.md` 保存即生效；`npm run assistant:check` 核对指南里引用的按钮名是否还在界面上，并拦截密钥和地址；`--ask` 跑回归问题。

## 4. 模式

### 4.1 等待与进度

核查要 5–15 分钟，等待页必须让人相信"它在干活"，并且有东西可读。

**进度来源，按可信度从高到低**

1. `GET /v1/credibility/assessments/{id}/progress` 返回的三项检查各自完成与否、开始时间，以及检查内部的小步（按用途统计的模型调用次数和最近一步）。都是真实事件。
2. 主接口的 `stage`：queued → retrieving → parsing → checking → finalizing → done。
3. 预计时间：核查阶段按经验时长估计。GPT 的大致时长是：主张约 2.5 分钟，代码约 1 分钟，引用约 7 分钟。

**规则**

- 估计出来的进度**最多走到 90%**，并且越接近越慢，不能显示成 100%。只有收到真实事件才能显示完成。
- 估计的进度和真实的进度外观一样，数字不加额外标注；总表盘按各项通常耗时加权汇总。
- 不要编造后端没做的步骤。日志里的每一行都必须对应一个真实阶段或真实事件。
- 一直显示已运行时间和"通常需要多久"。
- 五维评分和核查并行，是细分列表里的第 4 行 "Quality"（计入总表盘的 10%）。它通常 1 分钟就完成：完成时插入一行日志，该行右侧变成 "View"，可以马上打开五维报告。没有发起五维时不显示这一行。
- 用户可以随时离开：标题栏标签保留这次运行（见 4.3），标签上继续显示进度饼图和百分比，轮询不停。
- 可以单独停止一项检查：细分列表里运行中的那一行，末尾有一个安静的方形按钮（悬停变红）。点了在列表下方原处确认（"Keep running" / "Stop check"）。停止约 1 秒内生效；该项记为"你停止的"（行内写 Stopped，日志写 "Code check stopped by you"），得兜底分 3，不算发现；其余检查继续，报告照常生成。报告的 Process record 组件里写 "Stopped by the user"。
- 可以手动停止：表盘下方的 "Cancel assessment"，点了先在原处确认（"Keep running" / "Stop"）。停止后这次运行记为失败、代码 `CANCELLED`，在页面和 History 里中性地写 "Cancelled"（不标红），可重试。

### 4.2 兜底与缺口

- "查出的问题"（`kind = concern`）：红色，计入 "Concerns found"。
- "核实缺口"（`verification_gap`）与兜底分：石板灰加斜纹，计入 "Verification gaps" 和 "Fallback scores"。
- 文案上一律说 "could not be verified"，不说 "failed" 或 "wrong"；并且注明 "not the same as wrong"。
- 总分旁边永远写 "Trial score"，并在 "Score derivation" 里给出算式。

### 4.3 页面转场（容器变换）

用浏览器原生 View Transitions API（`document.startViewTransition`），给前后两页的同一元素起同一个 `view-transition-name`，浏览器自动做放大缩小。不支持的浏览器直接切换，不做替代动画。

| 从 | 到 | 共享元素 | 动作 |
|---|---|---|---|
| 开始页输入卡 | 加载页进度面板 | `check-<id>` | 卡片放大成面板（提交成功后才给输入卡这个名字） |
| 加载页进度表盘 | 报告页判定组件里的总分仪表 | `score-gauge` | 进度表盘原地变形为总分仪表，位置移到右侧 |
| 加载页进度面板 | 标题栏里该核查的标签 | `check-<id>` | 面板缩进标签 |
| 运行中的标签 | 加载页进度面板 | `check-<id>` | 从标签放大回来 |

每个核查用自己的名字 `check-<id>`：同一页面上同名的元素只能有一个，同时运行多个核查时不会冲突。

时长 300ms，曲线 `ease-easy-max`；其他元素用 150ms 淡入淡出。同一时间只放大或缩小一个元素。

### 4.4 失败与空状态

- 失败页（可信度核查和五维评分同一样式）：
  - 标题说清发生了什么（按错误码映射到英文标题）。
  - 一句后端给的原因。
  - "No credibility score or risk category was produced."
  - 下一步：可以重试的错误给 "Try again"，其他错误给 "Check another paper"。
- 超出评估范围（`UNABLE_TO_ASSESS`）用中性灰，不用红。
- 空状态（没有历史报告、没有证据）：一句话说明原因，再给一个可以做的操作。不放插画。
- 地址不存在（404）："There is no page at this address"，给 "New assessment" 和 "Assessment history" 两个出口。
- 页面渲染出错：标题 "This page could not be displayed"，说明核查数据不受影响，显示错误信息（等宽小字），给 "Reload page" 和 "New assessment"。
- 打不开的核查地址不会在标题栏留下标签；标签只为真正加载到的核查打开。

- 面板下方两块：
  - 两块等宽等高。
  - 左：五维评分卡。说明它是什么（更快的学术质量评估，不影响可信度分），下面列出五个维度，每个一条凹槽：运行中是带流光的空槽，完成后按分数填满并写出分数。运行中不再画第二根进度条，而是一个禁用的按钮 "Opens when ready · 23%"，左边的小饼图跟着进度走；完成后整卡描蓝边、标 "Ready"，显示分数、评级、阅读建议，按钮变成 "Read the quality assessment" 主按钮（切到 Quality）；失败给 "Retry"；没发起给 "Run quality assessment"。
  - 右："While you wait"，最近 4 份已完成的核查和 History 入口。

| 中间 | PDF 阅读区，证据高亮 |
| 右侧（默认 344px，可拖动调宽 280–480px） | 组件区，顺序为：Verdict → Claims → References → Code → Evidence → Process record → Notes → Add widget |
| 最右 | `WidgetRail` |
| 底部 | `StatusBar` |

- 断点：
  - 宽度 ≤ 920px：左侧面板改为浮层。
  - 宽度 ≤ 760px：运行栏去掉模型和时间，状态胶囊只留分数；≤ 560px 时两个开关只留图标和分数（名字留给读屏）。
  - 宽度 ≤ 700px：单列，PDF 在上，组件在下，两侧导航栏隐藏；PDF 页宽跟随屏幕，不能把整页撑出横向滚动。
  - 任何宽度下顶部工具栏放不下时换行（搜索框可缩到 120px），不撑宽页面。
  - 宽度 ≤ 900px 时标题栏标签保持可读宽度（最宽 150px），标签条横向滑动，不挤成一排图标。
- **Report 视图**：左侧目录，右侧是一张白纸样式的可信度报告，与打印版第一部分相同（见 5.5），滚动时目录高亮当前章节。窄屏时目录隐藏。
- Quality：五维报告（与 5.6 同一组件，标题较小），只有文档一种读法；运行中显示进度；失败给 "Retry quality assessment"；没发起给 "Run quality assessment"（上传的论文需要这个浏览器里的 PDF 副本）。五维不再作为组件放在组件区。
- Report 视图只放可信度部分（结尾附运行信息）；两部分合在一起的是导出版本（5.5）。
- 上传的 PDF 存在这个浏览器里（IndexedDB，保留最近 12 份），刷新或从历史打开都能显示原文。后端没有读回上传文件的接口，所以换一个浏览器就没有副本。
- 没有 PDF 时：中间区域改为"证据摘录"列表并说明原因。如果是上传的论文，顶部给 "Select the PDF"，选回同一个文件即可在原文里阅读，并存进这个浏览器。

### 5.4 历史列表 `/reports`

- 一行一次运行：Paper（标题 + arXiv / PDF）、Model（厂商标志 + 名称）、Credibility、Quality (5-D)、Started。
- 两个部分各自显示状态：已完成显示分数和类别 / 评级（点开对应标签）；失败显示 Failed 和原因；五维失败给 "Retry"、没跑给 "Run"。单独发起的五维是没有可信度部分的一行。
- 配对规则，按可信程度：① 服务端记录的关联（五维创建时带 `credibility_assessment_id`，详情和历史都返回；同一次运行重试过的五维取最新一份）；② 发起的浏览器记下的配对（也覆盖还在跑、尚未进历史的五维）；③ 没有前两者的旧记录，按"标题相同或一方是另一方的前缀（至少 12 个字符）且 10 分钟内先后发起"识别，猜测结果不再写回本地。一对一、按时间就近匹配，所以同一篇论文的不同批次不会混在一起；失败的五维也归到它的运行。
- 可搜索；可按类型筛选。
- 点击行打开报告。
- 运行中的运行：历史接口只列已结束的核查。这个浏览器知道的运行（打开的标签，或某条五维所属的运行）会单独取回；还在跑的排在最上面，可信度一栏写 "Running · n%"（带饼图），五维留在同一行，不会被当成"没有可信度部分"的单独一行。运行中的不能删除（按钮置灰，提示先取消）。
- 删除：每行最右一个垃圾桶按钮。点了整行变浅红，标题下写明后果（"Deletes both assessments of this run from the server. This cannot be undone."），按钮换成 "Keep" / "Delete"。
  - 删除顺序：先删五维、再删可信度，所以五维还在跑时（409）什么都不删，只提示等它结束。已经不存在的部分（404）当作已删除。
  - 删除后同时关掉它的标题栏标签、忘掉配对、删掉这个浏览器里存的 PDF。
  - 运行中的核查不出现在历史里；要删先在等待页停止。

### 5.5 可打印报告 `/check/$id/print`

- 由 Export → "Report (PDF)" 在新标签页打开，字体加载完后自动弹出打印对话框，选择 "Save as PDF" 即得 PDF。
- A4，边距 16 × 14 mm；不显示标题栏和任何界面控件。
- 第一部分是可信度核查，第二部分是同时发起的五维评分（另起一页）；没有五维时第二部分写明原因。打印前等五维结束（或确认没有），保证 PDF 完整。
- 最后是"Run details"，只有两行：可信度和五维各自的模型（附实际调用的版本号）与开始—完成时间。
- "Raw data (JSON)" 导出 `{ run, credibility, quality }`：同一次运行的两份记录原样打包。
- 第一部分内容顺序：论文信息（标题、arXiv、页数、日期、模型、耗时、评分规则）→ 判定（分数、等级、三个计数、分数推导）→ 1. 主张（每条：判定、理由、原文与支持段落引文及页码）→ 2. 参考文献（统计与未核实条目表）→ 3. 代码与复现（检索范围表）→ 4. 发现汇总（问题逐条列出；缺口按标题合并计数并指向所在章节；背景类发现已在主张理由里，不再重复）→ 5. 局限 → 出处（报告与核查 ID、生成时间、合同版本）。
- 引文、表格行不跨页断开；单条主张可以跨页，标题和小标签不与下文分开。这样不会留下大片空白。
- 引用标题超过 180 字时截断（解析失败时标题可能是一整段正文）；未核实原因用可读说法（`reasonName`），不显示内部代码。


### 5.6 五维评分 `/score/$id`

- 和其他页面同一套视觉，文档式单列页面，不用阅读器布局（五维的证据只有页码和摘录，不需要逐条在原文里定位）。
- 属于某次运行的五维评分打开时跳到那次运行的 Quality 标签；`/score/$id` 只用于单独发起、没有配对核查的五维。
- 顶部：小标题 "Quality assessment · five dimensions"、论文标题、作者、一行元信息（arXiv 或文件名、页数、评分规则、模型、完成日期）。如果这个浏览器里有配对的可信度核查，给一个 "Credibility assessment of this paper" 按钮。
- 判定卡：左边小号总分仪表（见 3.1），右边阅读建议、总结、理由、置信度与计算方式；暂定分和解析说明用灰色说明条。
- 正文左侧是章节目录（滚动时高亮当前章节；点击的章节保持高亮直到用户自己滚动；滚到底时高亮最后一节），右侧依次：论文摘要 → 五个维度 → 优点与问题（两栏）→ 主张核对 → 声称的贡献 → 可复现性 → 待解问题 → 局限。
- 维度：每行一个凹槽细条，白色细缝标出 5.5 / 7 / 8.5 三个分带，分数每次进入视野都重新数一遍；没有评分的维度只写 "Not scored" 和原因。
- 证据：小标签写 "Supports · p. 5 · 小节名"，点击后在下方展开引文卡（原文或转述、位置、理由），可复制引文；arXiv 论文还能 "Open page N on arXiv"。一次只展开一条。
- 进行中：卡片里一条带流光的细进度条加百分比和当前阶段；失败用 4.4 的失败页。

## 6. 文案

- **界面语言**：英文，英式拼写（colour、analyse、licence），与现有文案一致。
- **大小写**：句子式（"Start assessment"），不用标题式（"Start Assessment"）。
- **语气**：学术、中性、描述事实，像论文审稿意见或机构报告。不用设问句、口号和拟人说法（不写 "Does this paper hold up?"、"Three checks, side by side"、"Got it"、"magic"、"instantly"）。
- **示例**："Credibility assessment for machine learning papers"、"Scope of the assessment"、"Score derivation"、"Estimated 3–7 min remaining"、"Claims check complete (partial coverage)"、"An unverified reference does not indicate an error."
- **不确定的说法**：
  - "could not be verified"，不说 "failed"。
  - "Trial score"，不说 "score"。
  - "No concern was identified"，不说 "Passed"。
- **数字**：分数保留一位小数（6.7）；百分比取整；时长写成 "7 min 30 s"。
- **术语表**：

| 中文 | 界面用词 |
|---|---|
| 主张 | claim |
| 证据 | evidence / passage |
| 参考文献 | reference |
| 兜底分 | fallback score |
| 试验分 | trial score |
| 核实缺口 | verification gap |
| 查出的问题 | concern |
| 一次完整核查 | assessment |
| 三项中的一项 | check（claims / references / code check） |
| 五维评分 | quality assessment (five dimensions) |

## 7. 无障碍

- 文字对比度至少 4.5:1。`muted` 文字只放在白底或 `canvas` 底上。
- 每个可交互元素都有清楚的焦点框：2px `accent` 外框，外偏移 2px。
- 键盘可以操作：
  - 列表行用 Enter 或空格打开。
  - 分隔条支持方向键。
  - 菜单可以用 Esc 关闭。
- 进度变化通过 `aria-live="polite"` 播报，只播报阶段变化，不播报每一秒。
- 图形化的分数一定同时有数字文字；只用颜色表达的信息一定同时有文字。
- 遵守 `prefers-reduced-motion`（见 2.8）。
