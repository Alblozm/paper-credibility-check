# 帮助助手：知识库维护

右下角的帮助助手只回答"怎么用 PaperTrace、怎么看报告"。它不连评分后端，也不读数据库：每次提问时，服务把**整份操作指南**
`guide.md` 放进系统提示，再加上当前页面的几行摘要（报告页才有），交给模型回答。所以助手答得准不准，几乎完全取决于
`guide.md` 写得对不对、跟界面同不同步。

界面和助手回答统一使用英文。用户可以用其他语言提问，助手仍用英文回答；用户自己输入的问题、笔记不需要改写。
`server.mjs` 的系统提示固定该语言要求，发送上下文时忽略旧会话中的中文助手回复，并在流式输出发给页面前拦截中文回答。
如果模型未遵守语言要求，页面收到英文重试提示，原始问题仍保留。修改服务逻辑后需要重启服务；指南内容仍可自动重新加载。

| 文件 | 作用 |
|---|---|
| `guide.md` | 知识库本身（英文，Markdown）。助手只能说这里写了的东西 |
| `server.mjs` | 独立小服务（Node 20+，无依赖，默认 8020 端口）。`guide.md` 一保存就自动重新加载，不用重启 |
| `check.mjs` | 检查脚本：`npm run assistant:check` |
| `questions.json` | 回归问题：每条是一个问题和答案里必须出现的词 |
| `feedback.jsonl` | 用户对回答点的"有用 / 没用"，连同问题和回答（只在运行服务的机器上，不进 git） |
| `src/features/assistant/Assistant.tsx` | 前端对话窗；`usePageContext` 决定附带哪些页面摘要 |

## 什么时候要改知识库

只要用户看得到的东西变了，就要同步改 `guide.md`。包括：

- 新增、删除功能，或者改了按钮、标签上的文字；
- 改了流程，比如要先停止才能删除；
- 改了评分规则或类别的说法。

后端内部的改动（换模型、改提示词）只要不影响用户的操作和读到的内容，就不用改。

## 怎么写

- **按用户的任务分节**（`## Starting an assessment`、`## Reading the report`……），不按代码模块分。新功能放进它所属的任务里，不要另起一节"新功能"。
- **按钮和标签用双引号原样写**（如 `"Stop check"`）。检查脚本会逐个到 `src/` 里核对，界面改名而指南没跟上时会报错。双引号只留给界面上真实存在的文字；浏览器自己的文字（如 "Save as PDF"）登记在 `check.mjs` 的 `NOT_LABELS` 里。
- 写清楚**会发生什么、记录成什么**，不只写怎么点。例如停止单项检查："记为你停止的，得兜底分 3，不算发现"。
- 只写事实。不写还没做的功能，不写数字承诺，界面上没有的说法也不写。
- 不写任何密钥、服务地址、链接或第三方服务的信息。检查脚本会拦 `http(s)://`、`sk-…`、`Bearer …`。
- 控制篇幅：上限 24,000 字符，因为整份指南随每个问题发送。宁可删掉过时内容，也不要往上叠加。

## 改完以后

```bash
npm run assistant:check
```

这一步只做静态检查，不调用模型：

- 引号里的标签在不在界面里；
- 有没有密钥或地址；
- 每节是否非空；
- 篇幅是否超限。

不通过时退出码为 1。

服务在运行时，保存 `guide.md` 就会自动生效，日志会打印新的版本号。也可以查看当前用的是哪一版：

```bash
curl -s http://127.0.0.1:8020/assistant/health
```

改动较大时，再跑一遍回归问题。这一步会真实调用模型，每个问题算一次，同一地址 5 分钟内最多 20 次：

```bash
npm run assistant:check -- --ask
```

新功能上线时，在 `questions.json` 里加一两条对应的问题，并写明答案里必须出现的按钮名。保留非英文提问的回归问题，核对助手仍使用英文回答。

## 用反馈找知识库的漏洞

每个回答下面都有"有用 / 没用"两个按钮，点击会写进 `assistant/feedback.jsonl`，一行一条。每条记录包含：

- 时间；
- 评价；
- 回答时用的指南版本号；
- 所在页面；
- 问题和回答。

定期看一下被点"没用"的记录。按原因分别处理：

- 答错了：通常是指南没写，或者写得有歧义，去补 `guide.md`；
- 问的是指南范围以外的事：不用处理；
- 同一类问题反复出现：把它加进 `questions.json`，以后作为回归问题。

```bash
grep '"rating":"down"' assistant/feedback.jsonl
```

## 启动

```bash
npm run assistant
```

它会读取 `../backend/.env` 里的 `OPENAI_*`（如果存在）。也可以用 `ASSISTANT_API_KEY` / `ASSISTANT_BASE_URL` /
`ASSISTANT_MODEL` / `ASSISTANT_PORT` 单独配置。开发时 Vite 把 `/assistant` 代理到这个端口。服务没启动时，对话窗会提示暂不可用，其他功能不受影响。

## 边界

- 每个地址 5 分钟内最多问 20 次。
- 每次最多保留 12 条消息，每条最多 2000 字。
- 页面摘要最多 3000 字。
- 回答最多 900 个 token。
- 页面摘要只包含：分数、类别、问题与缺口数、兜底项、运行状态。不发送论文全文，也不发送用户笔记。
- 对话只存在当前标签页（sessionStorage）。只有用户点了评价，那一问一答才会写进 `feedback.jsonl`。
